# Reference

## A worked check, end to end

**Claim:** every finding in the handover has a table row carrying a `file:line`-shaped reference.

**Command**, keyed on the row, not on the string appearing somewhere:

```bash
jq -R -s --argjson ids '["r9","r7","r8"]' \
  'split("\n") as $l
   | $ids
   | map(. as $id
         | {id: $id,
            ok: ([$l[] | select(test("^\\|\\s*`?" + $id + "`?\\s*\\|"))
                       | select(test("[A-Za-z0-9_./-]+\\.(ts|js|svelte|json|md):[0-9]"))]
                 | length > 0)})
   | map(select(.ok | not) | .id)
   | if length == 0 then "PASS" else ("FAIL — no row with a file:line for: \(.)\n" | halt_error(1)) end' DOC.md
```

**Break it deliberately.** Copy to scratch, delete the `file:line` from *one row* (the structure
the claim names) and run against the copy:

```text
FAIL — no row with a file:line for: ["r9"]
```

Exit status 1.

**Record that output.** It is the evidence the check works. Discard the scratch copy; never mutate
the artifact itself. Then run against the real file and expect `PASS`.

Deleting a random character instead would also have produced red, and would have proven nothing.

## The scope-capture bug, correctly fixed

```bash
# BROKEN — `.` inside select() is the line, so every line contains itself. Always PASS.
jq -R -s --argjson m '["phrase one"]' \
  'split("\n") as $l | $m | map(select([$l[] | select(contains(.))] | length == 0))' DOC.md

# ALSO BROKEN — binding `.` does not help if it is bound in the same scope.
#   . as $x | select(contains($x))

# WORKS — the needle is bound in an outer scope and tested in an inner one.
jq -R -s --argjson m '["phrase one","phrase two"]' \
  'split("\n") as $lines
   | $m
   | map(. as $needle | select([$lines[] | select(contains($needle))] | length == 0))
   | if length == 0 then "PASS" else ("FAIL — missing: \(.)\n" | halt_error(1)) end' DOC.md
```

`. as $needle` binds inside `map` over `$m`, where `.` is a marker. The inner `select` then has
`.` = a line and `$needle` = the marker. Two scopes is the whole trick.

If the marker list lives inside the document you are checking, it matches its own copy. Strip
fenced regions first, or keep the list outside the file.

## Claims that cannot become commands

Most claims in a handoff or spec: "the reader will have enough to start", "this is simpler". The
command form for these is a **question with an answer key fixed before anyone answers it**.

Write five questions whose answers the artifact must supply. Write the expected answers down
first; this is what stops you grading to fit. Then ask readers, and score. A reader who answers
wrong, or who has to ask, has found a defect in the artifact rather than failed a test.

## Cold reader prompt

```text
Read exactly one file: <ABSOLUTE PATH>

Read nothing else. Do not explore the repository. You have no prior context about this
work and are not expected to.

Bash constraints if you use it: grep, cat, find, sed, awk, rg, head, tail, wc are
hook-blocked; no && / || / ; chaining; one command per call.

<THE QUESTIONS, or the lens below>

Be blunt and specific, and name the section. An empty answer is valid if there is
genuinely nothing there — do not invent findings to seem useful.
```

Vary the lens across readers rather than the wording:

- **Contradictions:** instructions that cannot both be followed, cross-references pointing at the
  wrong section. Quote both sides.
- **Prerequisites:** you must start real work tomorrow from this alone; what is missing that
  blocks you?
- **Unfalsifiable:** which success conditions can be satisfied without doing the work? Say exactly
  how someone would.
- **Unsupported:** what is asserted without evidence? Separate what the artifact flags as
  unverified from what it states flatly.
- **Different model:** pass `model` to the Agent tool. This is the only reader that can catch a
  blind spot belonging to the model rather than to the context.

## Adjudicating

Verifiers told to "refute if you can, default to refuted" return nothing useful: one such run
rejected all ten findings it saw while thirteen were real. Ask instead: is the claim accurate about
what the text says, and would it cost a competent reader real time? Refute only when it is
factually wrong about the text or is purely stylistic. Ambiguity in a handover counts as a defect.

Cite the artifact line that settles each finding. An adjudication with no citation is a preference.

## Evidence for the claims in SKILL.md

**Self-review does not catch your own errors.**
[*When Can LLMs Actually Correct Their Own Mistakes? A Critical Survey of Self-Correction of LLMs*](https://arxiv.org/html/2406.01297v3),
Kamoi et al., TACL. Conclusion quoted verbatim: "no prior work shows successful self-correction of
responses from LLMs using feedback generated by prompting themselves under fair settings in general
tasks", and "the bottleneck is in the feedback generation". Self-correction succeeds where reliable
external feedback exists (execution, symbolic checking) or where a response decomposes into parts
whose verification is cheaper than their generation.

**Verification runs on shallower machinery than generation.**
[*The Validation Gap: A Mechanistic Analysis of How Language Models Compute Arithmetic but Fail to
Validate It*](https://arxiv.org/abs/2502.11771). Models compute in higher layers but validate in
middle layers, before the result is fully processed, relying on "consistency heads" that assess
surface-level alignment of values rather than correctness.

**The 0% / 75% / 97% figures.**
[*The Compliance Gap: Why AI Systems Promise to Follow Process Instructions but Don't*](https://arxiv.org/abs/2605.01771),
Kwan Soo Shin, arXiv 2605.01771, 3 May 2026. Its opening example: an auditor instructs an assistant
"open each file individually using the Read tool — no scripts, no agents", the assistant replies
"Yes", then issues a single batched call over all fifty files. Across six frontier models,
instruction compliance under standard conditions was **0%**; one model "verbally agrees ten out of
ten times then bypasses in all ten". Compliance reached **97%** where rationale was rewarded via
audit trails, against 0–4% where it was not, and **75%** when delegation tools were removed:
"environmental affordances matter more than model weights". Theorem 1 argues the gap is structurally
inevitable under RL that rewards text without observing behaviour, and that it is not detectable
from text alone. Ships with BS-Bench, which the authors describe as the first benchmark measuring
process fidelity rather than outcome fidelity.

**Decorrelated readers beat a single agent.**
[Anthropic, *How we built our multi-agent research system*](https://www.anthropic.com/engineering/multi-agent-research-system):
a multi-agent configuration "outperformed single-agent Claude Opus 4 by 90.2% on our internal
research eval", at roughly 15× the tokens of a chat interaction. That eval is internal, unpublished,
and a browsing/information-gathering task rather than document review; treat the transfer as
directional, not measured.

**Caveat that applies to all four.** These describe a performance gap and one proposed mechanism for
it. None of them was run on this skill, this repository, or this task. They justify preferring
external signals over re-reading; they do not establish that any particular check you write works.
Only step 2 does that.

## Budget

Each reader re-reads the whole artifact, so cost scales with size × readers. Four or five lenses on
one document is a round. Anthropic measured a multi-agent configuration beating single-agent by
90.2% on an internal browsing eval at roughly 15× the tokens of a chat interaction, a different
task shape from document review, so treat it as directional: decorrelated readers are worth real
money, on artifacts where being wrong is expensive.
